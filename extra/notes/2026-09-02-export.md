# metha export

Written 2026-09-02, after the sweep. The sweep fills the cache nightly; this is
the verb that turns the cache into the thing that gets published. It replaces a
shell pipeline that has produced every metha corpus so far:

```shell
$ fd . '/data/.cache/metha' -e xml.gz | parallel unpigz -c | xmlstream -D
```

That pipeline works, and it is worth being precise about what it cannot do,
because each of those is a requirement rather than a complaint:

- **It cannot say where a record came from.** It reads files, and an OAI-PMH
  record carries a header, a metadata element and an about — nothing that names
  the repository. In one endpoint's output that is fine. In a corpus of 326M
  records drawn from a quarter of a million repositories it means no line can be
  attributed to anything.
- **It cannot filter.** No `--from`, no setspec, no deleted policy. The store
  answers all three from the index, and the pipeline is below the level where
  the index exists.
- **It cannot tell a shard it failed to read from one that held nothing.** Both
  contribute zero lines and neither says so, which is the property you least
  want in the step that produces an archival artifact.

## the shape

`metha export` is `metha cat` over every endpoint at once: `store.List` for the
targets, `store.Render` per target, one writer. The engine is in
`internal/cli/export.go` rather than a package of its own, for the reason
`migrate`'s pool is: nothing is injected, nothing else calls it, and there is no
`serve` waiting for it the way there was for `sweep`.

**The provenance field is the point.** `store.RenderOpts` grew an `Endpoint`,
and `renderRecord` marshals a `jsonRecord` — the record embedded, so its own
fields stay at the top level in their order, with `endpoint` appended — when it
is set. A consumer reading `.header.identifier` does not notice the field
arrived. `--no-endpoint` leaves it out, and then the output is byte-identical to
`metha cat --json`.

XML output ignores it. An attribute on the record element would change the shape
of the record itself, and a corpus is exported as JSON; the `--xml` mode exists
so that `export` is `cat`'s superset, not because anyone should ask for one
document holding a quarter of a million repositories.

**Parallel readers, one writer, and the invariant between them.** Workers render
into a `chunker`, which accumulates whole lines and ships a block at 256KB. That
threshold is not tuning: `Render` calls `Write` exactly once per record with the
entire line, so *any* threshold keeps a chunk line-aligned, and the size only
decides how often the writer is woken. What it also buys is a memory bound —
without it, a repository with two million records would be rendered whole before
a byte of it could be written.

That invariant is the one thing in here that would corrupt an artifact silently
if it broke, so it is tested directly (`TestChunkerKeepsLinesWhole`) rather than
only through the command: every chunk must end on a newline, and the reassembled
chunks must equal what was written.

**Ordering is not promised between endpoints, and is deterministic within a
run of `--jobs 1`.** `store.List` walks the tree in `os.ReadDir` order, which is
sorted, so a single-worker export of an unchanged cache is reproducible.

## three distinctions the summary makes

The pipeline had one outcome; this has four, and they were worth separating
because the actions differ.

| | means | exit |
|---|---|---|
| exported | records written | 0 |
| **matched nothing** | read fine, the filter excluded everything | 0 |
| **never harvested** | `store.ErrNotHarvested` — the cache holds nothing for it | 0 |
| **could not be read** | a real failure: pre-1.0 layout, a corrupt index, I/O | **non-zero** |

The last row is why the verb exits non-zero at all. Every other outcome is a
complete dump; a partial one that says so only in a line of stderr is a partial
one that gets published as a whole one.

**The third row was a correction made after running it.** `ErrNotHarvested` was
being counted as a failure, which is defensible for `metha cat` — you asked
about one endpoint and it has no data — and wrong here. `metha endpoints` prints
URLs the *sweep* knows about, and most of those have never been harvested
successfully; piping that list into `export` is the composition the README
recommends, and it exited non-zero with 244,039 "failures". The store already
distinguishes the two cases carefully (`store/v2_read.go:18`, and the comment
above it makes exactly this argument); the export just had to read it. Named
endpoints are printed up to ten and counted after that, on the same reasoning as
`Report.Unfinished`.

## measured

Against a real cache harvested by `metha sweep --limit 12`:

| | |
|---|---|
| 842 records, 2.0MB rendered | 57ms |
| written as `corpus.ndjson.zst` | 326KB |
| a 244,040-line endpoint list, one of them harvested | 916ms |

The zstd is klauspost's, already a dependency for the roster; the external
`zstd` CLI reads what it writes. Compression follows the output file's
extension — `.zst`, `.gz`, or none — because the name is what the file will be
read by, and a dump named `.zst` that is not zstd is worse than an uncompressed
one. stdout is left alone: a pipeline can compress it, and guessing there would
mean guessing from nothing.

## what it does not do

- **No record-level analysis.** Formats, sets, datestamp coverage, duplicate
  detection across endpoints — all of it is a consumer of this output, not part
  of it.
- **No `--format all`.** An identity is matched exactly, the way it is
  everywhere else: an endpoint harvested in two formats is two groups, and
  exporting both into one stream would produce lines that no longer agree about
  what their metadata element holds.
- **No resume.** A six-hour export that dies is re-run. `--endpoints` with the
  remainder is the manual answer, and it is enough until someone wants it.
- **No sorting or deduplication.** The published
  `2026-02-23-oaiscrape-unique.jsonl.zst` was deduplicated after the fact; that
  is a pass over the output, and it needs a key that this does not have to
  choose.
